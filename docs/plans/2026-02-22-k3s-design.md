# Design: k3s/k8s Worktree Framework

**Date:** 2026-02-22
**Branch:** k3s

## Overview

Two-part implementation:

1. **Section 1** — Extend `scripts/wt` into a generic framework that adds k3d/k8s namespace isolation to any git project, with minimal per-project configuration via `.wt/config.sh`.
2. **Section 2** — Set up `data-engineering-boilerplate` to use the framework: convert docker-compose services to k8s manifests (`k8s/infra/`) and a per-worktree Helm chart (`charts/worktree/`).

---

## Section 1: `wt` Script Extension

### Approach

Extend the existing single-file `scripts/wt` bash script in-place (Approach A). All new k8s/hook behavior is gated on `.wt/` existing, so repos without it continue to work as pure git worktree managers (backwards compatible).

### `wt init`

Scaffolds `.wt/` in `REPO_ROOT`:

```
.wt/
  config.sh            ← template with all documented vars + sensible defaults
  hooks/
    on-create.sh       ← build images → clone DB → helm install → wait for pods
    on-delete.sh       ← helm uninstall → drop DB (idempotent)
    on-status.sh       ← tab-separated headers or per-worktree pod status
```

All hooks are fully functional out-of-the-box; no edits needed beyond `config.sh`.

### Branch Name Sanitization

`earl/FIB-123` → `earl-fib-123`: lowercase, `/` and `_` → `-`, strip non-`[a-z0-9-]` chars, collapse repeated `-`, strip leading/trailing `-`.

### `wt create <branch> [--go]`

New steps inserted after git worktree creation:

1. Sanitize branch → `WT_NAME`
2. If `.wt/config.sh` exists: source it, derive `WT_NAMESPACE=${NAMESPACE_PREFIX}-${WT_NAME}`
3. `kubectl create namespace $WT_NAMESPACE` (idempotent via `--dry-run=client -o yaml | kubectl apply -f -`)
4. Export `WT_NAME`, `WT_BRANCH`, `WT_NAMESPACE`, `WT_PATH`, `WT_REPO_ROOT`
5. Execute `.wt/hooks/on-create.sh` if present; non-zero exit aborts with clear error
6. `--go` behavior unchanged (EVAL: pattern)

### `wt list`

- If no `.wt/hooks/on-status.sh`: fallback to `git worktree list`
- Otherwise: build formatted table
  - Call `on-status.sh --header` → tab-separated column names
  - For each worktree: derive `WT_NAMESPACE`, call `on-status.sh` → tab-separated values
  - Print with `column -t -s $'\t'`

### `wt delete <branch>`

New steps before existing git cleanup:

1. Derive `WT_NAME`, `WT_NAMESPACE`, export env vars
2. Execute `.wt/hooks/on-delete.sh` if present; non-zero exit aborts
3. `kubectl delete namespace $WT_NAMESPACE --ignore-not-found`
4. Existing `worktree remove` + `branch -d`

### `wt switch <branch>` — unchanged

### Hook Contracts

**`on-create.sh`** receives env vars: `WT_NAME`, `WT_BRANCH`, `WT_NAMESPACE`, `WT_PATH`, `WT_REPO_ROOT`

Logic:
- For each entry in `SERVICES`: `docker build` then `k3d image import -c $CLUSTER_NAME`
- Clone DB: `kubectl exec -n $INFRA_NAMESPACE $PG_POD` to `createdb` + pipe `pg_dump | psql`
- `helm install $WT_NAME $WT_REPO_ROOT/$HELM_CHART --namespace $WT_NAMESPACE --set worktreeName=...,branch=...,dbName=...,infraNamespace=...`
- Wait loop for pods ready (5-min timeout)

**`on-delete.sh`** receives same env vars

Logic:
- `helm uninstall $WT_NAME --namespace $WT_NAMESPACE --ignore-not-found` (or check first)
- `kubectl exec -n $INFRA_NAMESPACE $PG_POD` to drop the worktree DB (idempotent)

**`on-status.sh`** receives same env vars + optional `--header` flag

Logic:
- `--header`: print `NAME\tSTATUS\t<INFRA_SERVICES...>\tSENSORS` (tab-separated)
- Default: query pod status per infra service in `$INFRA_NAMESPACE`, count running sensors in `$WT_NAMESPACE` via `-l type=sensor`

### `config.sh` Template Variables

```bash
CLUSTER_NAME="dev-cluster"
NAMESPACE_PREFIX="wt"
INFRA_NAMESPACE="infra"
SERVICES=()           # "image-name:path/to/Dockerfile"
PG_POD="postgres-0"
PG_USER="postgres"
TEMPLATE_DB=""
HELM_CHART="charts/worktree"
INFRA_SERVICES=()     # label selectors for wt list
```

### Constraints

- `set -euo pipefail` throughout all scripts
- Keep existing `EVAL:` pattern for `--go` and `switch`
- `git -C "$REPO_ROOT"` for all git commands
- `branch -d` (safe delete, not `-D`)
- Explicit `-n <namespace>` on all kubectl commands
- Missing hooks silently skipped; non-zero hook exit aborts with clear error
- No `.wt/` directory → skip all k8s/hook behavior, pure git mode

## Section 2: Repository Setup

### Approach

Plain YAML manifests for one-time infra (`k8s/infra/`), Helm chart for per-worktree services (`charts/worktree/`). StatefulSet for warehouse to get stable `warehouse-0` pod name for `kubectl exec` in DB-clone hook.

### `k8s/infra/` Manifests

| File | Kind | Notes |
|------|------|-------|
| `namespace.yaml` | Namespace | `name: infra` |
| `zookeeper-deployment.yaml` | Deployment | `confluentinc/cp-zookeeper:7.4.4` |
| `zookeeper-service.yaml` | Service | ClusterIP, port 2181 |
| `kafka-deployment.yaml` | Deployment | `confluentinc/cp-kafka:7.4.4`, readinessProbe via `kafka-topics --list` |
| `kafka-service.yaml` | Service | ClusterIP, port 9092 |
| `kafka-init-job.yaml` | Job | Creates 4 topics, waits for Kafka, `restartPolicy: Never`, `backoffLimit: 3` |
| `minio-deployment.yaml` | Deployment | `minio/minio:latest`, PVC at `/data` |
| `minio-service.yaml` | Service | ClusterIP, ports 9000 + 9001 |
| `minio-pvc.yaml` | PersistentVolumeClaim | 5Gi, ReadWriteOnce |
| `warehouse-statefulset.yaml` | StatefulSet | `postgres`, readinessProbe `pg_isready`, pod name `warehouse-0` |
| `warehouse-service.yaml` | Service | ClusterIP, port 5432, headless for StatefulSet DNS |
| `warehouse-pvc.yaml` | PersistentVolumeClaim | 5Gi, ReadWriteOnce |
| `warehouse-configmap.yaml` | ConfigMap | Embeds `schema/tables.sql` + `schema/config.sh` verbatim |

Password via `kubectl create secret` only — not in any YAML file.

### `charts/worktree/` Helm Chart

```
Chart.yaml                        name: worktree, version: 0.1.0
values.yaml                       worktreeName, branch, infraNamespace, dbName, sensors[]
templates/sensor-deployment.yaml  range over .Values.sensors, label type=sensor
templates/pipeline-tests-job.yaml Job, same infra env vars, restartPolicy: Never
```

Sensor image tag: `{{ .name }}:{{ $.Values.worktreeName }}` — matches what `on-create.sh` builds and imports.

Env vars in both templates point to infra via DNS:
- `KAFKA_BOOTSTRAP_SERVERS=kafka.{{ $.Values.infraNamespace }}.svc.cluster.local:9092`
- `MINIO_ENDPOINT=minio.{{ $.Values.infraNamespace }}.svc.cluster.local:9000`
- `DATABASE_HOST=warehouse.{{ $.Values.infraNamespace }}.svc.cluster.local`
- `DATABASE_NAME={{ $.Values.dbName }}`

### `.wt/` for this project

`config.sh` as specified:
```bash
CLUSTER_NAME="dev-cluster"
NAMESPACE_PREFIX="wt"
INFRA_NAMESPACE="infra"
SERVICES=(
  "sensor-earthquake:./service/sensor_earthquake/Dockerfile"
  "sensor-tectonic-stress:./service/sensor_tectonic_stress/Dockerfile"
  "pipeline-tests:./service/pipeline_tests/Dockerfile"
)
PG_POD="warehouse-0"
PG_USER="postgres"
TEMPLATE_DB="earthquakes_prod"
HELM_CHART="charts/worktree"
INFRA_SERVICES=("kafka" "minio" "warehouse")
```

Hooks are the generic defaults from `wt init` — no project-specific overrides needed.

### Deployment Workflow

```bash
# One-time infra setup
kubectl create namespace infra
kubectl create secret generic warehouse-credentials \
  --namespace=infra --from-literal=POSTGRES_PASSWORD=<password>
kubectl apply -f k8s/infra/

# Per-worktree (automatic via wt create)
wt create my-feature --go
# → git worktree + namespace wt-my-feature
# → builds 3 images, imports to k3d
# → clones template DB to wt-my-feature
# → helm installs chart
# → cd + claude

# Status
wt list
# NAME        STATUS   KAFKA    MINIO    WAREHOUSE   SENSORS
# my-feature  Healthy  Running  Running  Running     2/2

# Cleanup
wt delete my-feature
# → helm uninstall + drop DB + delete namespace + remove worktree
```
